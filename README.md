# Учебный frontend-проект

## Описание

Проект выполняется в рамках дисциплины «Фронтенд и бэкенд разработка».
Тема проекта: многостраничный сайт интернет-магазина или каталога услуг.

## Структура проекта

- `index.html` – главная страница;
- `catalog.html` – каталог товаров;
- `product.html`, `product-2.html` … `product-9.html` – страницы товаров (у каждого товара своя страница);
- `order.html` – страница оформления заявки;
- `contacts.html` – контактная информация;
- `css/style.css` – основные стили;
- `css/responsive.css` – адаптивные стили (Mobile First), подключаются после `style.css`;
- `js/main.js` – JavaScript модального окна на главной странице;
- `js/order-form.js` – доступная валидация формы на странице заявки;
- `js/card-states.js` – переключатель «В избранное» (состояние «выбрано» у карточки);
- `js/image-fallback.js` – запасная иллюстрация, если фотография товара не загрузилась;
- `js/responsive.js` – кнопка меню на узких экранах и сворачиваемый фильтр каталога;
- `images/` – изображения товаров: SVG-иллюстрации (запасной вариант) и фотографии в `images/photos/`;
- `lighthouse/` – отчёт Lighthouse (Accessibility) после исправлений;
- `.gitignore` – список файлов, исключённых из Git;
- `README.md` – описание проекта.

## Адаптивная вёрстка (практическая работа 12)

Адаптивные стили вынесены в отдельный файл `css/responsive.css`. Он подключается на всех страницах после `style.css`, поэтому его правила переопределяют базовые. Используется подход Mobile First: базовые правила написаны для телефона, а для больших экранов добавляются медиазапросы с `min-width`.

Контрольные точки:

| Ширина | Что меняется |
|---|---|
| до 480px | одна колонка, кнопки на всю ширину, меню за кнопкой «Меню» |
| от 480px | кнопки формы в одну строку |
| от 640px | карточки и отзывы в две колонки, фильтры в две колонки |
| от 768px | форма заявки в две колонки, таблица сравнения — обычная таблица (на телефоне это карточки) |
| от 1024px | три колонки карточек, боковой фильтр слева |
| от 1100px | меню в одну строку, шапка закрепляется |

Что адаптировано:

- **Viewport.** На всех страницах есть `<meta name="viewport" content="width=device-width, initial-scale=1.0">`.
- **Навигация.** На экранах уже 1100px меню сворачивается за кнопку «Меню» (`aria-expanded`, `aria-controls`, закрытие по `Esc` и по выбору пункта). Без JavaScript меню остаётся развёрнутым. Пункты меню — крупные области нажатия (не меньше 44px).
- **Hero-блок.** Заголовок масштабируется через `clamp()`, кнопка на телефоне занимает всю ширину.
- **Сетка карточек.** CSS Grid: 1 → 2 → 3 колонки; `minmax(0, 1fr)` и `overflow-wrap: anywhere` не дают длинным словам ломать карточки.
- **Каталог.** На телефоне фильтр стоит перед товарами и сворачивается (`<details>`), на ноутбуке он раскрыт и закреплён слева.
- **Изображения.** `max-width: 100%`, `height: auto`, `picture` с `source type="image/webp"`, `srcset` с дескрипторами ширины (`320w` и исходный размер) и `sizes`, `width`/`height` против скачков макета, `loading="lazy"` для карточек ниже первого экрана. Если фото не загрузилось, подставляется запасная SVG-иллюстрация.
- **Форма заявки.** Поля шириной 100%, высота от 44px, шрифт 16px (iOS не увеличивает страницу при фокусе), на планшете и выше — две колонки.
- **Таблицы.** Таблица характеристик в контейнере `.table-wrapper` с горизонтальной прокруткой. Таблица сравнения на телефоне превращается в набор карточек (подписи берутся из `data-label`, роли ARIA сохраняют табличную семантику).
- **Модальное окно.** Ширина `min(100% - 32px, 560px)`, высота ограничена, длинное содержимое прокручивается.

Проверенные ширины: 360px, 430px, 768px, 1024px, 1440px. На всех страницах нет горизонтальной прокрутки, консоль без ошибок.

Вес фотографий: исходные JPEG — около 217 КБ, WebP — около 99 КБ, уменьшенные WebP (320px) — около 47 КБ. Браузер сам выбирает подходящий файл (в DevTools → Network → Img видно, что на ширине 1440px при обычной плотности пикселей загружаются файлы `*-320.webp`).

## Доступность (практическая работа 13)

Проверялись изображения с `alt`, использование ARIA и результат аудита Lighthouse (категория Accessibility).

### Изображения и alt

Проверены все 13 страниц: на сайте 21 изображение товаров (3 на главной, 9 в каталоге, по одному на каждой из 9 страниц товаров). У каждого есть непустой осмысленный `alt` с названием товара, например `alt="Беспроводная мышь Click Mini"`. Декоративных изображений в разметке нет: значок кнопки «Меню» нарисован средствами CSS и скрыт от скринридера через `aria-hidden="true"`. Фотографии обёрнуты в `<picture>`, а `alt` стоит на внутреннем `<img>`; запасная SVG-иллюстрация подставляется в тот же `<img>`, поэтому описание не теряется.

### ARIA: только там, где без неё не обойтись

Где возможно, использована обычная семантика (`header`, `nav`, `main`, `section`, `button`, `label`, `fieldset`/`legend`, `caption`/`th scope`), а ARIA добавлена, только когда у HTML нет нужного средства:

| Где | Атрибут | Зачем |
|---|---|---|
| Пункт меню текущей страницы (`index`, `catalog`, `contacts`, `order`) | `aria-current="page"` | скринридер сообщает, на какой странице пользователь (раньше текущая страница отличалась только цветом) |
| `<nav>` | `aria-label="Основная навигация"` | подпись области навигации |
| Кнопка «Меню» | `aria-expanded`, `aria-controls` | состояние и связь с открывающимся списком |
| Кнопка «☆» в карточке | `aria-pressed`, `aria-label="Добавить в избранное: …"` | у кнопки нет текста, только символ; состояние «выбрано» |
| Модальное окно | `aria-labelledby` на `<dialog>` | имя окна берётся из его заголовка |
| Поля формы с ошибкой | `aria-invalid`, `aria-describedby` | связь поля с текстом ошибки (в `order-form.js`) |
| Таблица сравнения на телефоне | `role="table"`, `row`, `cell` и др. | при `display: block` часть браузеров теряет табличную семантику |

Лишних ролей на элементах, у которых уже есть нужная семантика (`role="button"` на `<button>`, `role="navigation"` на `<nav>`), нет.

### Lighthouse

Запуск: Lighthouse 12.8.2, категория Accessibility, режимы Mobile и Desktop, все 13 страниц. Аудит запускался из консоли на локальном сервере (`http://localhost`), поэтому в отчёте адрес `localhost`. Кроме Lighthouse, дополнительно проверены открытое меню, открытое модальное окно и форма с ошибками (axe-core) и проход по страницам клавишей Tab.

Оценки до исправлений: `catalog.html` – 93, `index.html` – 95, `product-2.html` и `product-7.html` – 97, остальные страницы – 100. После исправлений – 100 на всех страницах в обоих режимах.

Найденные проблемы и исправления:

| Проблема Lighthouse | Где | Исправление |
|---|---|---|
| Background and foreground colors do not have a sufficient contrast ratio | зелёная метка «Новинка» (белый текст на `#168a2f`, контраст 4.46:1) | в `css/style.css` цвет `--color-success` изменён на `#147a2a` (контраст 5.46:1, норма WCAG AA – 4.5:1) |
| Heading elements are not in a sequentially-descending order | `catalog.html`: заголовок блока «Фильтры» был `h3` сразу после `h1` | заменён на `h2`, внешний вид сохранён правилом в `css/responsive.css` |

Отчёт после исправлений (главная страница, Mobile) сохранён в папке `lighthouse/`: `accessibility-report.html` – полный отчёт Lighthouse, `accessibility-report.png` – его скриншот.

Что Lighthouse не проверяет, проверено вручную: логичный порядок Tab, видимый фокус (`:focus-visible`) на ссылках, кнопках и полях, открытие модального окна с клавиатуры, закрытие по `Esc` и возврат фокуса на кнопку «Заказать».

## Проверка адаптивности (практическая работа 14)

Проверены все 13 страниц на ширинах 360, 430, 768, 1024 и 1440 px (65 проверок, `viewport` и `responsive.css` подключены на каждой странице). Проверка выполнялась в браузере автоматически (Playwright) и дополнительно просматривалась на скриншотах.

| Что проверено | Результат |
|---|---|
| Макет страниц | горизонтальной прокрутки всей страницы нет ни на одной ширине; ни один блок не выходит за экран |
| Шапка и меню | на ширинах до 1100 px меню за кнопкой «Меню», на широком экране – в одну строку |
| Изображения | все фото загружаются, не выходят за контейнер (`max-width: 100%`), заданы `width` и `height` |
| Responsive images | `picture` + `srcset` + `sizes`: на каталоге при 1440 px браузер берёт уменьшенные файлы `*-320.webp` (около 47 КБ на 9 фото), на телефоне и планшете – полные WebP (около 99 КБ вместо 217 КБ у JPEG) |
| Форма заявки | на 360 и 430 px одна колонка, от 768 px две; поля не выходят за экран, высота 44 px, шрифт 16 px, у каждого поля есть `label` |
| Таблица характеристик | лежит в контейнере `.table-wrapper` с `overflow-x: auto`, страницу не растягивает |
| Таблица сравнения | до 767 px превращается в карточки, от 768 px обычная таблица и помещается без прокрутки |
| Консоль | ошибок JavaScript нет |

Что исправлено по итогам проверки: на планшете (768 px) таблица сравнения на страницах товаров была шире экрана и обрезалась с правого края. Теперь обычный вид таблицы включается с 768 px, на ширинах 768–1023 px ячейки сделаны компактнее (меньше внутренние отступы), и таблица помещается целиком.
